# Canvas and workspace implementation

## Scope and criteria

- **#3 consumer lifecycle:** Stream requests have an AbortController. Unmount/workspace changes abort the stream; stale callbacks, validation completions, catch/finally and Stop responses cannot update a new workspace or newer run. Premature EOF/stalls mark only pending/running nodes `interrupted`, clear busy, and expose a separate Stop backend run control because a lost observer does not prove the backend stopped. Successful/failed nodes keep their results. Renderer recovery leaves the workspace-owned observer and remote-run controls intact. Workspace navigation reconciles actual backend run status before enabling Run. Transport errors use the shared structured error helper.
- **#5 recovery / #7 health integration:** Palette, canvas, inspector and dock have separate shared ErrorBoundary instances. Graph, persistence and execution ownership sit in WorkspaceDetailPage above those boundaries. An additional boundary around ReactFlow preserves the canvas toolbar on graph-renderer failures; parent Stop/Reconnect controls survive broader pane failures. The engine indicator subscribes to the shared live health monitor.
- **#8 extraction:** PipelineCanvas is 615 lines (previously 1,523). Rendering and starters moved to CanvasRenderers/starterWorkflows. Pure graph layout/validation/payload/history logic and workspace-scoped save sessions have direct tests. Graph/history, persistence and run responsibilities use dedicated hooks. Templates stay with the canvas's small template UI; activityStore was not changed.
- **#9 selection:** One graph reducer owns node/edge selection, graph and history. Inspector derives its selected data directly from the graph. Direct hook callbacks replace both mutable command refs and parent/internal selection echoes. Deleting or undoing clears stale selection; parameter updates retain selection.
- **#10 fetching:** Run selection causes no requests. Refresh reads depend on workspace only, abort superseded loads and reject late responses. Catalog reads use transport's session cache and cancellation support. Canvas and template reads are cancelled. Run/trim/delete/branch results are guarded against workspace changes. Save sessions keep their original workspace and serialize writes; debounce and unmount flush cannot write old snapshots into another workspace. Failed canvas reads show Retry and pause saving to protect the existing persisted graph.
- **#11 validation:** Graph compatibility/cycles/schema parameter types, enum/ranges and declared required values are evaluated automatically. Server validity is debounced on semantic payload changes; Run is disabled with an inline reason until valid. Invalid connections are marked. Manual Validate remains. Execution separately validates modal overrides and server graph validity before requesting the stream.
- **#12 cycles:** Kahn layout decrements indegrees and waits for all parents. A bounded DFS returns a closed cycle path and offending edge IDs; pure/self/reachable cycles block Run and preserve positions instead of freezing. Edge badges say Creates a cycle. Diamond dependencies have no false positive.
- **#13 branch:** onBranch calls branchRun. Matching uses canonical tool IDs and requires selected-node disambiguation when a tool occurs twice. Source params are restored; compatible saved artifact paths become downstream file inputs. The source appears completed with its saved output provenance and is excluded from execution, together with upstream nodes; only descendants run. This never assigns a file to the downloader URL. Feedback states source run, artifact count and pre-filled downstream steps. Unsupported missing matches, incompatible artifacts, terminal-only steps and multi-parent dependencies report an actionable error; backend supplies one tool run, not full multi-step resume. Canonical translator flow discovery was also corrected.
- **#16 artifacts:** Discarded artifact state and both discarded fetch paths are gone. Trim/run/delete refresh actual dock and media consumers through mediaRefreshKey (dock refresh implementation owned by coordinator).

## Limitations / manual acceptance

The automated gate does not substitute for a browser test of a real backend disconnect during a five-node pipeline, pane crash recovery or a failed three-step branch followed by real execution. Coordinator owns browser and integration checks, typography/color migration and final build results. Branching deliberately reports unsupported multi-parent dependencies rather than inventing absent outputs. Session cancellation and stale-result guards protect the frontend; aborting the SSE observer does not itself stop a remote process, hence the explicit backend Stop control.
