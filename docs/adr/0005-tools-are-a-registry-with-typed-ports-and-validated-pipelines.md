# Tools are a registry with typed ports; pipelines are validated chains

Tools are registered in a central catalog; each tool declares its name, parameter schema, accepted input kinds, and produced output kinds. A Pipeline in a Workspace is an ordered chain of tools where consecutive steps connect an output port to a compatible input port; the UI offers only compatible next tools and rejects invalid chains. Port types follow an open file-kind model (audio, video, text, folder, any — subkinds included) rather than a closed enum, so artifacts behave like ordinary files in an opened folder. Adding a tool is a developer action: a manifest plus a driver, registered in the repo. Considered and rejected: curated recipes only (too rigid — kills free composition), unconstrained free chaining (users would wire incompatible tools and get confusing failures), and a closed type enum (too rigid for an open catalog).
